# W0-003 — Add `mutmut` configuration to `pyproject.toml`

## Problem

`mutmut` is now pinned as a dev dependency (W0-002), but it has no project-level configuration. Running `mutmut run` without configuration mutates every Python file under `src/resume_ranker` and runs the full test suite, which:

- Includes non-scoring packages that are not the target of the QG1/QG2 scoring mutation gate (QA_PLAN §4.2).
- Triggers tests that depend on runtime data files the mutation workspace does not copy by default.
- Produces a noisy, slow report and makes it impossible to verify the `scoring/**` ≥ 90 % threshold per gate.

## Impact

- The mutation gate cannot be run reproducibly as part of `make qa-gate` or `scripts/qa/mutate.py`.
- Component agents cannot verify their own mutation scores against the published thresholds.
- The generated `mutants/` workspace is not ignored by default and would be picked up by `git status`.

## Proposed fix

Add a `[tool.mutmut]` section to `pyproject.toml` that:

1. Restricts mutation to `src/resume_ranker`.
2. Copies `data/` into the mutation workspace so tests that import data at collection time can still run.
3. Narrows `pytest_add_cli_args` to the scoring unit tests and the two QA scoring tests that do not require full pipeline data fixtures.
4. Ignores `mutants/` via `.gitignore` so generated mutation files are not committed.

## Decision

Approved by project lead. Implementation owner: W0.

## Implementation

`pyproject.toml`:

```toml
[tool.mutmut]
source_paths = ["src/resume_ranker"]
only_mutate = ["src/resume_ranker/scoring/*"]
also_copy = ["data/"]
pytest_add_cli_args = [
    "-m", "not slow",
    "-q",
    "tests/unit/scoring_evidence",
    "tests/unit/scoring_aggregate",
    "tests/unit/scoring_semantic",
    "tests/unit/scoring_profile",
    "tests/qa/test_oracle_smoke.py",
    "tests/qa/test_differential_scoring.py",
]
```

`.gitignore`:

```text
# Mutation testing workspace
mutants/
```
