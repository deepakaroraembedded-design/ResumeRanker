# Contract-change C-15-001: Unowned test file `tests/test_fakes_satisfy_protocols.py` fails lint

**Date:** 2026-08-29  
**Component:** C-15 (CLI / config / pipeline)  
**Severity:** Build-blocking

## Problem

`make gate` fails at the lint stage on `tests/test_fakes_satisfy_protocols.py`, which is not listed in the §2.2 ownership map. The file is a Wave-0 test and imports the `tests.fakes` package, but it is not under `tests/fakes/`, `tests/conftest.py`, or `tests/corpus/`.

`ruff check` reports:

```
tests/test_fakes_satisfy_protocols.py:1:1: I001 Import block is un-sorted or un-formatted
```

The first-party imports are ordered `tests.fakes` before `ats_scan.protocols`; Ruff expects the reverse (alphabetical within the first-party group).

## Impact

- The lint gate is red on the `contracts-frozen` base, so every component branch starts with a failing `make gate`.
- As C-15 I cannot edit the file (it is outside my owned paths), so I cannot resolve the failure locally.

## Proposed resolution

1. Add `tests/test_fakes_satisfy_protocols.py` to the W0 ownership entry in `scripts/check-ownership.py` and the §2.2 table (it is a Wave-0 protocol/fake test).
2. Re-order the first-party imports in the file so `ats_scan.protocols` precedes `tests.fakes`.

## Workaround in C-15 branch

C-15 is leaving this file untouched and will note the lint failure in the component report. All other owned paths are implemented and pass `make test`, `make types`, `make imports`, and `make schema`; only `make lint` remains blocked by this unowned file.
